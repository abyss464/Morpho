--- bulk_approve.py ---

# Batch Approval

For all unapproved selections (definition, example, image) in the working database, call the engine API item by item to perform approval.

## Usage
`python3 ops/bulk_approve.py`

No command-line parameters; configuration is via environment variables.

## Environment Variables
- MORPHO_API: engine API address (default `http://127.0.0.1:8787`)
- MORPHO_DB: working database path (default `data/working.db`)

## Behavior
1. Open the working database in read-only mode, and query all word items (target role, or auxiliary with aux_status active) where `approved=0` and `enabled=1` for definition selections, and `approved=0` for example selections and image selections.
2. For each recorded item, call the corresponding `POST /api/selections/{type}/approve` endpoint to approve it as `operator-approve`.
3. After the run completes, print the number of approved and failed selections for each type (with 409 counted separately).

## Output
Print summary lines to standard output in the format `definition: approved N, failed N (of which 409=N)`, one line for each of the three types.

## Side Effects
Selections will be marked as approved via the engine API. The database is not written directly.

## Note
409 indicates the engine rejected the approval (the current candidate is not in available status), which is expected and should not be treated as a fatal error.


--- cc3m_inflected_ingest.py ---

# CC3M Inflected Form Import

Imports CC3M inflected matching pairs (image + caption) into Morpho. Similar to cc3m_ingest.py, but highlights the word item's inflected form (e.g., for the lemma "abolish", the corresponding "abolished") rather than the base form.

## Usage

`python3 ops/cc3m_inflected_ingest.py`

No command-line parameters.

## Environment Variables

- MORPHO_API: Engine API address (default `http://127.0.0.1:30012/api`)

## Input

- `ops/logs/cc3m-inflected-accepted.json`: List of already-accepted pairs generated by cc3m_inflected_prepare.py. Each item record contains word_id, lemma, caption, matched_form, image_path, file_name, source_url.

## Behavior

For each item pair, perform the following four steps in order:

1. Upload the downloaded image as an image candidate.
2. Cast the CC3M caption as an example candidate (with UTF-8 byte offset highlighting of the inflected form).
3. Select the uploaded image as the word item's current image.
4. Cast the caption into example slot 1.

Items whose captions contain neither the inflected form nor the base form are skipped and not uploaded.

## Output

- `ops/logs/cc3m-inflected-ingest-results.json`: Summary results, including `total`, `uploaded`, `skipped`, error details, and unmatched details.
- Prints progress and a final summary to standard output.

## Side Effects

Creates candidates and modifies selections through the engine API. Operates as `local`.


--- cc3m_inflected_prepare.py ---

# CC3M Inflected Form Preprocessing

Prepare CC3M inflected match pairs for Morpho import. From the match results, filter for word items that are still stock-only and have not been directly overridden by CC3M matches, then download images and convert them to WebP.

## Usage
`python3 ops/cc3m_inflected_prepare.py`

No command-line parameters.

## Dependencies
Requires Pillow (`pip install Pillow`).

## Input
- `/tmp/cc3m_inflected_matches.json`: match results from the inflected override scan (mapping of lemma to match list)
- `/tmp/stock_only_words.tsv`: current stock-only word items list (format: `word_id|lemma`)
- `ops/logs/cc3m-accepted.json` (if present): word items already directly overridden by CC3M matches, used for exclusion

## Behavior
1. Load the stock-only word list, excluding word items already directly overridden by CC3M matches.
2. For each pending word item, sort candidate matches by title quality score (penalize illustration/vector categories and overly short titles, reward specific descriptions).
3. Download images in parallel (up to 16 threads), discarding those that are too small (<128px) or too large (>10MB).
4. Scale images to 512px on the longest side, then convert to WebP format (quality 80).

## Output
- `ops/logs/cc3m-inflected-accepted.json`: list of accepted pairs, for use by cc3m_inflected_ingest.py
- WebP image files under `/tmp/cc3m_inflected/webp/`
- Progress and final summary printed to standard output


--- cc3m_ingest.py ---

# CC3M Import

Import accepted CC3M (image + caption) pairs into Morpho.

## Usage
`python3 ops/cc3m_ingest.py`

No command-line parameters.

## Environment variables
- MORPHO_API: engine API address (default `http://127.0.0.1:30012/api`)

## Input
- `ops/logs/cc3m-accepted.json`: list of accepted pairs generated by cc3m_prepare.py. Each item record contains word_id, lemma, caption, image_path, file_name, source_url.

## Behavior
For each item pair, execute four steps in order:
1. Download the image and upload it as an image candidate
2. Cast the CC3M caption as an example candidate (with the lemma's UTF-8 byte offset highlighting, case-insensitive matching for all words)
3. Upload the selected image for that word item's current image
4. Cast the caption into example slot 1

Items where the caption cannot find all word matches for the lemma are skipped and not uploaded. Items where the image file does not exist are also skipped.

## Output
- `ops/logs/cc3m-ingest-results.json`: summary results, including total, uploaded, skipped, error details, and unmatched details.
- Standard output prints progress and final summary.

## Side effects
Creates candidates and modifies selections via the engine API. Operates as `local` identity.


--- cc3m_prepare.py ---

# CC3M Preprocessing

Prepare Conceptual Captions 3M pairs for Morpho import. Filter out word items that are still stock-only from the match results, download images and convert them to WebP, and select the best pair by title quality.

## Usage
`python3 ops/cc3m_prepare.py`

No command line parameters.

## Dependencies
Need Pillow (`pip install Pillow`).

## Input
- `/tmp/cc3m_matches.json`: the analyzer's match results (lemma to {word_id, matches} mapping)
- `/tmp/stock_only_words.tsv`: current stock-only word items list (format: `word_id|lemma`)

## Behavior
1. Load the stock-only word list, only process word items that have CC3M matches
2. For all matches of each word item, sort by title quality score (penalize illustration/vector categories, overly short titles, titles that only contain the lemma; reward sentence structure and concrete descriptive language)
3. Download images concurrently (up to 16 threads), discard images that are too small (<128px) or too large (>10MB)
4. Scale images to 512px on the longest edge, convert to WebP format (quality 80)
5. Take the first successfully downloaded and converted image for each word

## Output
- `ops/logs/cc3m-accepted.json`: list of accepted pairs, for use by cc3m_ingest.py
- WebP image files in the `/tmp/cc3m/webp/` directory
- Standard output prints progress and final summary


--- clip_rematch.py ---

# CLIP image re-match script

Re-scores image candidates against upgraded slot-1 sentences using CLIP cosine similarity. For each active word, embeds available image candidates and the slot-1 sentence (falling back to the lemma), picks the highest-scoring candidate subject to per-question visual distinctness, and re-selects when the new best beats the incumbent by a margin. Persists per-word outcomes to a report file. Human-reviewed pins (actor `admin:local`) are scored but never overridden. Mutations via the admin API; direct DB access is read-only.

--- fix_primary_pos.py ---

# Primary POS correction script

Moves each word's primary sense onto the part of speech the exam corpus actually uses, unsticking words stranded by a prior triage pass. Three passes: (1) enable the corpus-correct slot so rule 6 has somewhere to move to, (2) wait for a reconciler pass to move the primary (or force it via API for editor-placed primaries rule 6 cannot touch), (3) disable the old wrong-POS slot once the primary is confirmed on the new one.


--- mine_subs.py ---

# Subtitle Corpus Mining

Mine the best example for each target word from the OpenSubtitles corpus database.

## Usage
`python3 ops/mine_subs.py`

No command-line parameters; paths and parameters are controlled by constants at the top of the script.

## Constants
- DB: working database path (read-only connection)
- CORPUS: path to the gzipped OpenSubtitles English corpus
- OUT: output JSON path
- K: maximum number of candidate sentences retained per word item (default 8)

## Behavior
1. Read all word items from the working database where role=target or aux_status=active and that lack Chinese definitions.
2. For each word item, generate inflected forms (plural, past tense, progressive tense, etc.) and build a form-to-lemma mapping.
3. Stream-scan the entire gzipped corpus, scoring each line by length, punctuation, formatting, etc.
4. For each word item, retain the top K sentences by score.

## Output
Write a JSON file in the format `{lemma: [[score, sentence], ...], ...}`.

## Side Effects
- Read-only access to the working database
- Write the JSON file specified by OUT


--- nsfw_screen.py ---

# Image Database Content Screening

Multi-subcommand tool for screening inappropriate content, blank images, and text-dominated images in the image database, and supports manual review and batch rejection.

## Usage
`python3 ops/nsfw_screen.py <subcommand> [parameter]`

## Subcommands

### regate
`python3 ops/nsfw_screen.py regate <candidates.json> --out <results.json> [--apply] [--actor <name>]`

Performs blank detection and CLIP floor-score detection on a set of candidate image rows. Input is a JSON list containing img_cand_id, word_id, lemma, and file_hash. Output is a per-row pass/fail report. With `--apply`, the manage API is called to reject rows that did not pass.

### clip-sweep
`python3 ops/nsfw_screen.py clip-sweep --out <report.json> [--limit N]`

Uses the CLIP model to score all already-selected images against a set of inappropriate/neutral text probes, then outputs a full report sorted by margin. Only marks; it does not make any decisions or write anything.

### blank-scan
`python3 ops/nsfw_screen.py blank-scan --out <report.json> [--limit N]`

Scans the pixel standard deviation of all selected usable images, and marks blank (`confirmed_blank`) and near-blank (`near_blank`) images. Outputs a sorted report.

### text-scan
`python3 ops/nsfw_screen.py text-scan --out <report.json> [--limit N]`

Compares CLIP text probes against scene probes to identify text-dominated images. Only outputs a ranking; it does not automatically reject.

### contact-sheet
`python3 ops/nsfw_screen.py contact-sheet <word_ids.json> --out-dir <dir> [--per-page N]`

Generates paginated thumbnail grids (PNG) for the specified `word_id` list. Each thumbnail is labeled with `img_cand_id`, and currently selected items are marked `[SEL]`. Also writes `manifest.json` in the output directory.

### flagged-sheet
`python3 ops/nsfw_screen.py flagged-sheet <entries.json> --out-dir <dir> [--cols N] [--rows N] [--thumb N]`

Renders items filtered from the clip-sweep report as labeled thumbnail grids (PNG) for manual visual confirmation.

### reject
`python3 ops/nsfw_screen.py reject <to_reject.json> --out <log.json> [--actor <name>]`

Calls the manage API's rejection endpoint for each row in the input list and records the results in a log. This is the only subcommand that performs writes.

## Environment Variables
- `MORPHO_API`: manage API address (default `http://127.0.0.1:30012/api`)
- `MORPHO_DB`: working database path
- `MORPHO_MEDIA`: media file directory

## Side Effects
- The `regate --apply` and `reject` subcommands reject image candidates through the manage API.
- The remaining subcommands only read the data database and media files, and write report JSON or PNG files.


--- release.sh ---

# Release Pipeline

One-shot script that automates the full release pipeline (OPERATIONS.md §5–§6): health check, bulk approve, preview gate, export, copy release.db, sync media, patch ReleaseDatabaseTest.kt, specbook refresh, build + test, git commit.

## Usage

`ops/release.sh [--yes]`

## Parameters

- `--yes`: auto-confirm specbook interface changes (skip the interactive prompt)

## Prerequisites

- Docker engine running on port 30012 (`docker compose up -d`)
- `jq`, `sqlite3`, `curl`, `rsync`, `gio` available in PATH
- Android SDK configured for Gradle builds

## Pipeline Steps

1. Health check: `GET /api/dashboard`
2. Bulk approve: runs `ops/bulk_approve.py` with `MORPHO_API` pointing at the Docker engine
3. Preview gate: `GET /api/releases/preview`, fails if `gate_failures` is non-empty
4. Export: `POST /api/releases/export`, locates the newest `data/releases/export-*/` directory
5. Copy `release.db` to `app/app/src/main/assets/release.db`
6. Sync media (`img/`, `audio/`) to `app/content_media/src/main/assets/content_media/` — adds missing files via rsync, trashes removed files with `gio trash`, verifies zero missing and zero extra vs manifest
7. Patch `ReleaseDatabaseTest.kt` with counts from the new release.db (content_version, words, senses, examples, distractors, gloss_anchors, groups, learning_order density, highlight check)
8. Specbook refresh: runs `ops/specbook.py refresh --all`; hash-only changes proceed silently; interface changes pause for confirmation (or auto-confirm with `--yes`)
9. Build + test: `./gradlew :domain:test :app:testFatApkDebugUnitTest :app:assembleFatApkDebug :app:assembleFatApkRelease`
10. Git commit with message `ops: cut release <version>`, staging release.db, test file, and specbook files
11. Print summary: APK path, version, word count, media count

## Output

Prints step-by-step progress to stdout. Fails fast (non-zero exit) on any step failure.

## Side Effects

- Exports a release via the engine API
- Writes release.db, media files, and test assertions into the app module
- Creates a git commit (local only, no push)


--- translate_sentences.py ---

# Example Machine Translation

Translate the slot-1 examples of all active words from English to Chinese using machine translation, for use in the management interface's image review mode.

## Usage

`python3 ops/translate_sentences.py [--db PATH] [--out PATH] [--workers N] [--limit N] [--retry-missing]`

## Parameters

- `--db`: path to the working database (read-only; default `data/working.db`)
- `--out`: output JSON path (default `admin-ui/public/sentence-zh.json`)
- `--workers`: number of concurrent translation threads (default 6)
- `--limit`: translate only the first N rows/lines (for testing)
- `--retry-missing`: load an existing output file, translate only the missing `word_id`s, and merge the results back into the file

## Prerequisites

The `trans` command (translate-shell) must be available in the system `PATH`.

## Behavior

1. Query all active words' slot-1 examples from the working database.
2. Use translate-shell to translate concurrently; if a sentence fails, automatically retry by switching the engine among Google, Bing, and Yandex.
3. For full output, every rerun re-translates all current examples from the beginning (except in `--retry-missing` mode).

## Output

Writes a JSON file with the format `{"word_id": "Chinese translation", ...}`.

## Side Effects

- Read-only access to the working database
- Writes the output JSON file
- Calls an external translation service (via translate-shell)


--- unapprove_auto.py ---

# Revoke Auto Approvals

Allows releasing approvals generated by auto-selection, enabling the scheduler to re-select under a new scorer.

## Usage

`python3 ops/unapprove_auto.py [definition|example|image ...]`

When no parameters are passed, only `definition` is processed by default.

## Parameters

- Positional parameter: slot type. Options: `definition`, `example`, `image`. Multiple values can be passed.

## Behavior

1. Query all slots of the specified type with `approved=1` and `selected_by='auto'` from the work database (read-only).
2. For each item, call the manage API's `DELETE /api/selections/{type}/approve` endpoint to revoke the approval.
3. Print the number of successes and failures for each type.

## Typical Workflow

After a scorer version upgrade, run this script to release the auto-approval locks. Wait for the engine to converge under the new scorer, then re-run `bulk_approve`.

## Environment Variables

- `MORPHO_API`: manage API address (default: `http://127.0.0.1:30012/api`)

## Side Effects

- Revokes slot approvals via the manage API (releases the lock without deleting the selection itself).
